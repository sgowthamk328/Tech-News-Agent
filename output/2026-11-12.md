## AWS distills its cloud into a local emulator that runs on your PC

**Category:** Technical Release  |  **Found via:** The Register

Modern cloud application development often requires developers to constantly interact with remote cloud resources during testing. Every time software engineers want to check whether their code correctly interacts with cloud services, such as databases or object storage, they must either deploy their code to actual cloud infrastructure or use third-party simulation tools. Deploying directly to the cloud incurs financial costs for API calls and server runtime, introduces latency while waiting for remote provisioning, and requires constant internet connectivity. To solve these friction points, Amazon Web Services (AWS) launched the 'AWS Emulator,' an official lightweight utility designed to run locally on a developer's workstation or within automated Continuous Integration (CI) pipelines.

Architecturally, the AWS Emulator is written in Rust, a systems programming language known for its high performance and minimal CPU and memory footprint. The tool operates by serving a local API endpoint on the developer's computer. When launched, it automatically generates local cryptographic credentials, configuration files, and certificates. Developers redirect their existing AWS Software Development Kits (SDKs), command-line tools, or automated testing scripts to point to this local endpoint by adjusting environment variables. Because the application code itself remains unchanged, unit tests and development scripts execute seamlessly on the local machine without making outbound network requests to AWS servers or incurring cloud charges.

Under the hood, the emulator supports API models published in the official AWS GitHub repository, spanning over 1,300 service specifications. However, it is fundamentally an API mock rather than a complete local clone of the entire AWS hyper-infrastructure. It does not evaluate complex Identity and Access Management (IAM) permissions in the manner of live AWS, nor does it support multi-region or cross-account behaviors. To help developers understand how closely a local API response matches live behavior, AWS publishes 'fidelity scores' for supported services. Additionally, AI coding agents can utilize specialized skills to automatically audit codebase dependencies against these fidelity scores to highlight any potential discrepancies before deployment.

Who's involved: Amazon Web Services (AWS), Daniel Abib (AWS Senior Specialist Solutions Architect).

## Disgraced former CA eMudhra blames buggy script for hopelessly weak certificates

**Category:** Policy / Security  |  **Found via:** The Register

Digital security on the internet relies heavily on Public Key Infrastructure (PKI) and Certificate Authorities (CAs). CAs are trusted organizations responsible for issuing digital certificates that cryptographically verify the identity of websites and encrypt online communications. To maintain this web of trust, CAs generate public and private key pairs inside dedicated hardware devices called Hardware Security Modules (HSMs). When a CA's key generation procedure fails, the cryptographic guarantees that secure web browsers, enterprise data, and online services are severely compromised.

In a recent public disclosure on Bugzilla, former CA eMudhra revealed the technical failures behind its issuance of fatally flawed digital certificates. Faced with global supply chain delays that prevented them from obtaining preferred HSM hardware before a mandatory regulatory deadline, eMudhra attempted a workaround. They generated key pairs on one vendor's HSMs and used a custom Python script to wrap and unwrap those keys for transfer to another vendor's devices. A logic bug in the Python script truncated the generated private keys during read-back. Instead of producing robust 48-byte ECDSA P-384 private keys, the script reduced private keys to absurdly small values—including single-byte numbers like '4'—making them easily guessable and mathematically recoverable from public information.

This vulnerability fundamentally altered the security landscape for affected web infrastructure. Possessing a server's private key allows malicious actors to impersonate legitimate websites, decrypt private user traffic, and conduct man-in-the-middle attacks. Upon discovery by security researchers, major web browser vendors immediately revoked trust in eMudhra’s certificates, blocking them from validating web traffic globally. In response to the breach of trust and subsequent distrust by browser ecosystems, eMudhra officially announced its exit from the SSL/TLS certificate issuance business. Moving forward, the company is undergoing an independent operational review to audit its remaining internal PKI processes while winding down its commercial certificate operations.

Who's involved: eMudhra, Mozilla, Naveen Kumar ML (eMudhra representative), Utimaco, Crypto4A.

## Russian cloud Yandex says drone attacks on its datacenters caused data loss

**Category:** Industry News  |  **Found via:** The Register

Cloud computing relies on centralized physical locations called data centers, which house thousands of servers storing critical data and running software for businesses. Typically, cloud infrastructure is designed to be highly resilient against localized hardware failures through redundant systems and automated backups across different facilities, known as availability zones. However, physical disruptions caused by military conflict present unprecedented challenges to cloud service availability and data protection.

Russian cloud infrastructure provider Yandex revealed that physical drone strikes targeting its data centers resulted in a fire, server outages, and permanent loss of roughly 2.84 percent of customer data within its targeted facility. While Yandex successfully restored over 97 percent of impacted data, the incident exposed severe gaps in default backup configurations and platform resiliency during physical attacks. In response to the loss, Yandex has changed its platform policy to enable automated data backups by default for new virtual machines created by customers, though this increases resource usage and costs. The company is also promoting hybrid cloud architecture—where organizations maintain a mix of local, on-premises servers alongside cloud resources—to mitigate the risk of total data loss from localized physical destruction. Additionally, international tech sanctions have hindered the rapid procurement of replacement hardware needed to easily expand capacity in newly opened availability zones.

Who's involved: Yandex (Yandex Cloud).

## Hands on with Home Assistant’s new ‘smart home multi-tool’

**Category:** Technical Release  |  **Found via:** The Verge

Home automation platforms often struggle to integrate legacy electronics or isolated hardware standard protocols. Nabu Casa, the commercial entity backing the open-source Home Assistant platform, has introduced the Home Assistant Connect Aux-2—a $69 hardware box designed as a versatile bridge between non-smart hardware and smart home networks.

Underneath its compact enclosure, the Aux-2 operates on ESPHome, an open-source firmware framework optimized for microcontrollers. The device acts as a hardware interpreter by combining multiple connectivity layers into a single unit. It features standard networking options like 2.4GHz Wi-Fi, Ethernet with Power over Ethernet (PoE) support, and Bluetooth for bridging nearby wireless sensors. For physical connectivity, it incorporates USB ports that can host external Z-Wave or Zigbee radio dongles, allowing users to place network coordinators in optimal physical locations rather than tethered directly to a main server.

Crucially, the Aux-2 solves the problem of integrating legacy analog and serial infrastructure. It includes dual RS-232 serial ports, enabling bidirectional communication with enterprise or legacy equipment such as older AV receivers, solar inverters, and televisions. Additionally, a built-in digital/analog audio jack enables music streaming to legacy amplifiers, while a dedicated Grove expansion port allows direct interfacing with modular DIY hardware sensors, buttons, and status LEDs.

By abstracting complex hardware communication protocols into ESPHome components, the Aux-2 allows Home Assistant to discover and control offline devices without requiring custom wiring or complex microcontrollers built from scratch. This significantly lowers the barrier to extending smart automation deep into existing home infrastructure.

Who's involved: Nabu Casa, Open Home Foundation, Home Assistant, and ESPHome.

## United won’t let your AI agent book your flight

**Category:** Industry News  |  **Found via:** The Verge

As artificial intelligence shifts from informational chatbots to autonomous 'agentic' models capable of navigating websites and executing actions on a user's behalf, major consumer enterprises are facing unexpected friction. United Airlines recently declared that it will block unauthorized third-party AI agents from executing flight bookings on its platform. While these autonomous software agents can search and display flight options to users, they are prohibited from completing final commercial transactions.

This decision highlights a growing tension across the tech and service industries. Tech developers are heavily investing in autonomous shopping and scheduling assistants—such as Meta's Muse or OpenAI's agentic tools—aiming to automate consumer chores. However, service providers like United are balking at the security, liability, and regulatory implications. From an operational standpoint, airlines are mandated by federal regulations to ensure passengers acknowledge safety disclosures, such as confirming hazardous materials or explosives are not present in checked baggage. An AI agent cannot legally or functionally attest to these regulatory declarations on behalf of a human passenger.

Beyond safety regulations, corporate pushback stems from data privacy concerns, unintended purchases, and a strategic desire to prevent third-party tech platforms from acting as intermediaries between companies and their direct customers. United joins a growing list of major institutions, including eBay, DoorDash, and several large banking firms, that have placed technical or policy restrictions on autonomous bots interacting with their customer portals. As agentic AI becomes more pervasive, industry standards for identity verification, liability delegation, and authorized API access will need to be established before full transactional automation becomes standard across corporate ecosystems.

Who's involved: United Airlines, Scott Kirby (CEO of United Airlines), Meta, OpenAI, eBay, and DoorDash.
